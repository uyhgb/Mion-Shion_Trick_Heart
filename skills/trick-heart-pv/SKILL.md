# 魔术之心角色替换 PV

本 Skill 是**流程层**规则，建立在通用方法 Skill `ai-handdrawn-video`（waterpro/agent-anime-skill，需另行安装）之上：通用 Skill 负责「怎么做才不返工」的方法，本 Skill 规定这首歌、这种替换的阶段、硬规则和停顿点。线条抖动与质感还原见同仓库的 `pv-line-boil` Skill。

## 开工前读

1. 项目根目录的 `docs/00_进度看板.md`（若有）和 `AGENTS.md`：当前阶段、已定决策、环境坑。
2. `analysis/project-brief.json`：规格和决策记录 `decisions[]`。作者的决定只认这里。
3. 角色卡、叙事稿。
4. 可选：本仓库 `data/trick-heart-pv/` 的实测数据，只作线索，必须在自己的源片上核对。

新对话开工时，先用三五句话复述当前阶段、已定决策和环境注意事项，再动手。

## 阶段与停顿点

| 阶段 | 产物 | 停顿 |
| --- | --- | --- |
| P0 | 素材清单与哈希（保留作者的人工标注）、环境与生图能力实测、3 秒技术测试 | 不停 |
| P1 | probe、shots、timeline（唯一边界来源）、pose-events（逐帧，不猜循环）、layers（每个物体唯一来源）、text-cues（源像素保护）、storyboard（每镜对回叙事编号） | SP1 |
| P2 | style-guide、character-master（每个细节注明依据文件）、expression-map、母版、对照图、一帧合成试画 | SP2（作者批准后冻结） |
| P3-A | 难镜头样片：开场手牌、杂耍、醒来、结尾；源片和样片并排视频 | SP3 |
| P3-B | 七类镜头分批：静态跟踪 → 头像框 → 手部接触 → 背影风动 → 杂耍 → 帘幕沙发醒来 → 结尾 | 批间不停 |
| P4 | 合并、统一渲染、无声编码 + 原 AAC stream copy、78 个切点检查 | SP4 |
| P4s | 质感还原（见 `pv-line-boil`）：三个样镜 → 作者批准 → 分组推广 → 合并 | SP4s |
| P5 | 终稿小修、单次编码、对最终 MP4 验收、DELIVERY.md 与署名 | SP5 |

每个停顿点按统一格式汇报：完成、证据路径、实际看过的帧（原速、慢放、逐帧分开说）、未完成、需要作者决定的事（最多 3 条，附推荐选项）、下一步。然后更新进度看板并停下。

## 硬规则

**时间与来源**
- 原PV的背景、文字、非人物道具、转场、时间轴、BPM 和音轨全部保留；输出帧 n 等于源帧 n。
- 整数帧、左闭右开；帧率保留分数。
- 事实以源片实测为准；叙事稿、他人工程的帧号、自己的推测都只是线索；冲突要写进报告，由作者决定。

**角色与原画**
- 固定映射：`magician → 角色A / 服装A`，`casual → 角色B / 服装B`。源片里外观有变化的镜头（例如结尾换装、扎发）按作者批准的变体处理。
- 服装结构沿用原PV，逐项对照源帧：外套长度（没有燕尾）、手套和袖口、腿部的不对称、鞋。
- 母版冻结后只引用冻结清单（带哈希）。旧版标 superseded，不删除。
- 生图一律端到端，不把部件拼贴到别的角度或别的图上。
- 验收标准是「接近即可」；每张原画设尝试上限（默认 3 次，母版 4–6 次），到上限就停下报告。
- 游戏立绘和 CG 只当参考，不进合成器；颜色只从光照可信的立绘取；带敏感内容的参考只用于标注过的那一项用途。
- 不水平翻转角色图层。
- 原PV的表情事件全部保留；「演法」只改画法，不改表情本身。

**手和道具**
- 源像素复用：只露手、鞋、衣角的镜头沿用源片的手，只改袖子和服装部件；新画出来的前臂和袖口要带和原片同粗细的线稿（以源片该格为底图整张改图，不要程序填色）。
- 接触道具同图：接触期间，手和道具画在同一张原画里；道具独立运动时才用源道具层；按 pose-events 的帧切换来源，同一帧同一个道具只有一个来源。
- 整张原画已经合格时，作为一个图层整用，不再回盖源片的肢体。

**安全与发布**
- 生图工具拦截某张图时，停下报告，由作者决定改构图、人工补图还是接受近似；不要自行反复改写提示词去试。
- 不发布、不上传、不 git push；不把歌词全文写进任何文件。
- 正式输出不得回退到源人物、旧缓存或几何占位；缺图就报错，并说明是哪个镜头。

**交付**
- 先无声编码，再用源 AAC stream copy 独立封装，不重编码、不用 `-shortest`。
- 终稿只经过一次有损编码：所有帧都从无损流程渲染，不从已编码的预览解码再编码。
- 验收对象是实际的最终 MP4：probe、完整解码、帧数、音频包逐包比对、切点抽帧。如实写明没做的检查（例如没有连续目视、没有试听）。

## 并行

可以并行的：P3-B 的各批、P4s 的各时间段。

- 一条主线照常写共用文件（看板、生成日志、估算、状态、事件表、简报、公用脚本）；主线做完本批就停。
- 并行对话只写本批目录 `reviews/<批>/`、`assets/shots/<批>/`、`scripts/<批>_*.py`；共用文件只读。本批写 `generation-log.jsonl`、`art-estimate-delta.json`、`pose-events-corrections.csv`、`handoff.md`、`LOCK.json`（in-progress → done）。
- 全部 done 后，由一个合并对话核对「每个镜头只有一个来源」，把各批记录并回共用文件，再组装全片。

## 常见坑（详见仓库 docs/05）

母版与源帧不一致时以源帧为准；配饰大小不要自动收小；返工前先做量化对比（双眼对齐叠线）；杂耍的球必须由联合原画持有；只露手的镜头要检查新画部分是否静止不动。
